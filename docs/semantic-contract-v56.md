# Semantic contract: v56 static kernel and integral sparse algebra

This repository implements the static calculus-relative proof/context kernel described around Definitions 1.1--1.4, Proposition 1.5, the two root profiles, the address-indexed CK factorisation, compatible base extension, basis constructor deletion, and exact nullary-ground repair in the v56 manuscript. Above that kernel it implements finite integral sparse sums of proof forests and ordered forest tensors. The supplied PDF and TeX source are read-only mathematical references and are not part of the implementation.

## Implemented representation

- Formula contexts are canonical finite multisets of immutable formula data.
- A sequent is a pair of formula contexts. A hypersequent is a nonempty finite multiset of sequents. Equal displayed components retain distinct, local 1-based occurrence indices.
- A concrete occurrence has a unique registry key, a disjoint kind/tag, opaque fully instantiated data, an ordered vector of whole-hypersequent premises, one whole-hypersequent conclusion, and optional opaque incidence data.
- An equipped calculus is a finite immutable registry. Profile equality never grants admission: raw applications identify the exact registered occurrence key.
- Raw candidates use the Redex-friendly shared syntax `(puncture)` or `(app occurrence-key child ...)`. Checked nodes and typed holes are separate values whose constructors are private to the checker.
- Validation reports structured errors and checks registry membership, exact arity, exact ordered premise boundaries, and an optional expected root boundary. Checked terms expose root boundary, completeness, and vertex count.
- Punctures have positive premise-slot addresses (with `()` reserved for the typed nodeless identity), and their requirements are read from retained parent occurrences. The premise telescope sorts these address/whole-boundary pairs lexicographically.
- A corolla is one admitted occurrence with every premise vacant. Typed insertion prefixes the inserted context's internal addresses, context composition fills the current telescope, and complete filling requires a complete proof at every entry. These operations recheck exact boundary and registry provenance; their validity never depends on a filler search.
- Calculus provenance is retained for rechecking but excluded from structural proof-presentation equality. `term-admitted-by?` is only an extensional registry-admission query; it does not establish provenance identity. Operational insertion, forest construction, multiplication, and carrier-sensitive lookup require the exact same registry object with `eq?`. Cross-revision use requires explicit checked lifting first.
- A compatible calculus revision is an immutable source registry, exact withdrawn-ID set, fresh addition set, and internally constructed target `(K0 - D) + A`. Every retained occurrence is reused exactly; profile mutation, substitution, renaming, and component reindexing are absent. Historical validity remains source-relative, while target liveness checks every vertex's full occurrence identity and reports every retired, unknown, or incompatible/redefined address.
- Checked lifting is explicit rebasing: a source-certified live term or open context is converted to shared raw syntax and revalidated under the target with its exact root boundary. This preserves its presentation, addresses, puncture requirements, and telescope while changing registry provenance. No unchecked cast is exposed.
- Basis-level constructor deletion maps a historical positive-vertex checked node or proof-forest monomial either to a target-lifted survivor or to an explicit algebraic-zero value carrying the historical source and every withdrawn occurrence. A naked typed `Box^G` returns a structured domain error because it is not a basis tree. Term offenses retain their tree address; forest offenses retain a structural factor, its local address, and the factor multiplicity without imposing an order on the commutative forest. One affected factor kills the whole monomial, while the empty forest survives as the target algebra unit. This remains a diagnostic basis projection: it is not formal additive zero, and it is not yet extended linearly as a quotient or revision map.
- An automatic nonroot ground-repair plan exists only for a complete historical source proof whose every target-inactive occurrence is explicitly withdrawn, material, and nullary. Its inactive leaf addresses form the CK cut; the plan retains the complete source witness (aligned detached tuple, commutative forest, source remainder, and reconstruction data) and separately stores the exact same punctured presentation revalidated under the target. Positive-arity, logical, structural, incompatible, and non-prefix-free frontiers return structured scope errors before cut construction.
- Applying a plan takes complete, live proofs carrying the exact target registry, in lexicographic telescope order and with exact whole-hypersequent roots. Structural extraction succeeds precisely when a candidate has the plan's exact retained constructor identities and ordered premise structure, with arbitrary complete target proofs only at its punctures. Filling and extraction are inverse on this selected retained context, establishing the implemented product-of-fibres bijection; this is not a claim about every target proof with the same root.
- A one-vertex withdrawn ground uses a separate whole-proof replacement value retaining the historical source, target identity context `Box^G`, and telescope entry `((), G)`. This endpoint uses the same checked filling/extraction interface but is not a CK cut and does not change root-cut rejection or cut enumeration.
- A proof forest is a commutative finite multiset of positive-vertex checked connected terms carrying one exact equipped-calculus snapshot throughout. Multiplicity is retained. Its block-root profile remembers one hypersequent per connected factor, while its flattened root unions all displayed component occurrences. The empty forest has no `HSeq` flattened root, and a nodeless identity context is rejected as a factor. Forest construction never silently revalidates a foreign factor, and forest union rejects distinct registry snapshots even when they are structurally equal.
- A CK cut is a finite prefix-free set of existing nonroot vertex addresses in a complete or punctured positive-vertex derivation. A witness retains the sorted address/subtree tuple, its commutative forest image, and the punctured remainder. Empty cuts are included; root cuts are rejected because the whole-tree tensor endpoint is algebraic bookkeeping, not a cut. Witness reconstruction fills only the newly cut addresses, preserving any older punctures. Cut enumeration structurally generates a lazy sequence without scanning inadmissible subsets.
- An integral formal sum is one immutable, finite, normalized sparse value carrying an exact equipped-calculus snapshot and a positive tensor rank. Each support key is an immutable vector of proof forests of that rank, and each stored coefficient is an exact nonzero integer. Construction collects duplicate structural keys and removes zero coefficients; support access never exposes the mutable coefficient table used while normalizing.
- Rank one represents finite integral combinations of proof-forest basis elements. The formal additive zero is empty coefficient support tied to one exact calculus snapshot. The algebra unit is instead the nonzero basis element of that calculus's empty proof forest. A checked-node convenience injection first forms its singleton forest, so complete and punctured positive-vertex rooted terms are admitted while a naked typed `Box^G` cannot become a basis element.
- Rank-two and higher values retain tensor-coordinate order. Forest factors inside each coordinate remain commutative, but `(F,G)` is not identified with `(G,F)`. Addition, negation, subtraction, exact-integer scaling, and componentwise forest multiplication are normalized and require the same positive rank and the same exact calculus object. Coordinate expansion and contraction likewise preserve coordinate order and reject incompatible ranks, snapshots, or replacement results with structured algebra errors rather than treating incompatibility as zero.
- Formal-value operational identity includes exact calculus provenance even though checked terms and proof forests retain structural presentation equality. Consequently, formal zeros and otherwise identical-looking sums over distinct but structurally equal snapshots are different values and cannot be combined without explicit checked lifting and reconstruction in one selected snapshot.
- Forest multiplication in both the kernel and formal algebra is independent commutative juxtaposition. It is not context filling, assembly, Mix, witness reconstruction, Gentzen Cut, or any implicit structural proof rule. A connected proof of `S | T` remains distinct from a forest containing separate `S` and `T` proofs even when their flattened roots agree.

The implemented CK API still stops at occurrence-level witnesses. The sparse algebra can collect repeated structural tensor keys, but no CK coproduct currently converts cut witnesses into such a sum. When that collection is added, its coefficients will intentionally forget the address alignment that the existing witness API continues to retain.

The proof-tree carrier is cut-hereditary because admission is currently local: constructors are finite fully instantiated occurrences, every occupied child has the exact ordered premise boundary, typed vacancies remain valid without a filler, and no proof-global normality, freshness, or liveness condition restricts membership. Replacing a subtree by its typed vacancy therefore preserves local admission, and detached subtrees remain admitted. This claim must be reassessed if incidence metadata or a future calculus introduces nonlocal admission conditions; incidence is presently trusted occurrence metadata rather than an independently validated global constraint.

## Equality and indexing

The implementation uses structural proof-presentation equality. Boundary multisets absorb exchange and preserve counts. Component indices are deterministic local presentation indices; a future representation may implement the manuscript's more general equality by coherent component reindexing. Premise slots and tree addresses remain ordered even when their boundaries are equal. Forest factors are instead collected commutatively with multiplicity. Structural equality never proves shared calculus provenance: operational forest, formal-sum, and tensor APIs separately require exact `eq?` registry identity.
